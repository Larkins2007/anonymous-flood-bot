# Обновление Justice Faite Manager до 0.11.1

1. Перед заменой файлов сделай резервную копию SQLite и убедись, что свежий `JF_DB_BACKUP_V1` закреплён в личке владельца.
2. Замени код проекта содержимым архива v0.11.1. Не удаляй `users.db`/файл из `DB_PATH`, `.env`, Persistent Disk и переменные Render.
3. Сохрани текущие `BOT_TOKEN`, `ADMIN_ID`, `PRIMARY_CHAT_ID`, `DB_PATH` и настройки постоянного хранилища.
4. Миграции аддитивные. Существующие балансы жетонов, инвентарь, журнал операций, модерация, ресты, роли, награды, сообщества и питомцы сохраняются.
5. После запуска проверь логи и команды в тестовом чате: `/jf_social`, `.отн история связи`, `.отн запрос` (ответом), `.отн да`, `Действия`, `.отн пт`, `.отн пт похвалить`, `Дом`, `Ферма`, `Баланс`, `/settings`.
6. AI выключен по умолчанию. Внешний API-ключ не вставляй в сообщения, исходники или репозиторий.
7. Важно для Render: текущий `render.yaml` сохраняет план `free` и `JF_STORAGE_DURABLE=false`. Локальная SQLite на эфемерном диске не является постоянным хранилищем. Для долговечной БД нужен реально подключённый Persistent Disk/подходящий managed database; только после этого укажи абсолютный `DB_PATH` внутри mount path и установи `JF_STORAGE_DURABLE=true`. Не меняй один флаг без диска.
8. Сначала проверь новую сборку в тестовой группе. Живой деплой, реальные Telegram-права и восстановление с твоего Render-проекта этой сборкой не подтверждены.

Офлайн-проверки: `python -m compileall -q .` и Все 30 офлайн-тестовых модулей успешно прошли по отдельности с локальной SQLite и заглушками aiogram. Aggregate-runner в данной среде не был надёжно подтверждён. Проверка использует SQLite и заглушки Telegram; живой Telegram Bot API и Render в этой среде не запускались.
