# Next Generation — аудит охвата требований после 0.15.1

## Реализовано или частично реализовано

- Justice AI: явные обращения, контекст по недавним сообщениям/релевантным фрагментам, `reply`, `mention`, `text_mention`, стабильные псевдонимы участников между запросами, актуальные персонажные роли из `group_members`/`role_catalog`, отдельные внутренние ранги модерации, краткая оперативная история в RAM и две отдельные долговременные памяти. Стиль по умолчанию короткий и разговорный.
- Приватный AI владельца: настоящая проверка `from_user.id` и `chat.id`, использование существующего журнала ЛС и отдельной памяти владельца, сохранение ответов AI.
- Watch: более тихий цикл (120 с. по умолчанию), семантический анализ не чаще раза в 30 минут и от 20 сообщений, низкоуверенные сигналы хранятся без ЛС, ежедневная сводка, строгий cooldown для исключительных срочных сигналов. Слабые старые pending alerts переводятся в silent с сохранением доказательств. Санкций нет.
- Advisor: локальная статистика и история отчётов; расписание управляется через state DB; добавлены реальные session/start/terminal/conversion агрегаты для существующих Spyfall/Mafia таблиц.
- Self-Audit: ежедневная локальная проверка без Groq; владелец получает ЛС только при новой критической ошибке, одинаковая ошибка не повторяется бесконечно.
- Callback UI: тесты проверяют каждый сгенерированный экран `/settings` на дубли callback ID и 64-байтовый лимит; отдельные replay/idempotency тесты проверяют неизменяемые callback-действия.
- Память владельца и память флуда из 0.14.1 сохранены физически и логически раздельными; личная память не попадает в групповой контекст.
- Схема 0.15.0 использует существующие таблицы; 0.15.1 аддитивно добавляет `jf_ai_identity_aliases` и индекс стабильных псевдонимов. Существующие данные не переписываются.

## Частично / ограничения точности

- Не все случаи адресации можно разрешить: если нет `reply`, Telegram entity, username в архиве или однозначной ссылки, адресат остаётся неизвестным. Не угадывать по одному имени в тексте.
- `sender_tag` — вспомогательное поле и не является обязательным для распознавания роли. Сырой тег остаётся локально; текущая персонажная роль подтверждается по активной записи `group_members` и `role_catalog`.
- Семантический Watch использует батчи, локальные правила и ограниченный контекст; это не доказательство нарушения. Многострочные потоки и просьба остановиться остаются формальными эвристиками с риском пропусков/ложных сигналов.
- Изображения, мемы, стикеры, видео и аватары не проходят полноценное визуальное семантическое распознавание. Текст caption/entity может участвовать в контексте.
- Групповая память хранит только общий обзор сообщества, не персональные досье; приватная память владельца не экспортируется в групповой контекст.
- Сводка памяти может потерять нюансы при сжатии. Первичный архив и owner journal остаются источником; сводка — только ориентир.

## Пока не реализовано из Next Generation

1. Полная привязка всех команд проекта к расширенному единому реестру с фактическими диагностическими результатами для каждого зарегистрированного обработчика остаётся незавершённой.
2. Частично закрыто: все generated `/settings` keyboards проверяются на дубли callback ID и 64-byte limit; replay/idempotency проверены для текущих settings actions. Полный callback-handler overlap audit по всем модулям и runtime callback IDs ещё не завершён.
3. Частично закрыто: Self-Audit планируется ежедневно и сообщает только о новых критических локальных сбоях. Полный audit всех фоновых систем, интеграций, прав и runtime-конфигурации ещё не реализован.
4. Частично: есть `/settings`, owner console и команды диагностики; полной единой панели всех Next Generation подсистем пока нет.
5. Не реализован: полный repair-patch workflow с evidence graph, подготовкой локального diff, отдельным подтверждением правки и подтверждением deployment.
6. Не закрыто полностью: приложение умеет использовать `DB_PATH` и блокирует ложную декларацию durable для относительного пути, но default Render blueprint остаётся Free. Persistent disk или managed Postgres требуют платного/отдельного решения оператора; SQLite не переведён целиком на async/thread layer. Инструкция дана в `RENDER_PERSISTENCE_0.15.0.md`.
7. Частично: добавлены session/start/terminal/lobby-conversion агрегаты для существующих Spyfall/Mafia таблиц. Оценка успешности мероприятий/тем, обратная связь участников и сравнение эффективности интерактивов не реализованы, потому что соответствующие outcome/feedback данные не записываются.

## Проверки и границы

Офлайн-тесты не подтверждают работу живого Telegram API, Groq, Render, долгосрочную доступность файлового хранилища или эксплуатационную нагрузку. Роли и архив проверены на локальной резервной копии БД: в ней 32 активных участника с ролями из каталога, а в старой схеме архива отсутствует `sender_tag`; новая логика разрешает роль без этого поля. Обновление не коммитилось и не деплоилось.
