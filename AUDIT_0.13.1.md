# Аудит Justice Faite Manager 0.13.0 → 0.13.1

Статический аудит присланного архива и снимка БД (`justice_faite_memory.sqlite3`) + прогон тестов. **Живой Telegram, Groq, aiogram из `requirements.txt` и Render не проверялись** (офлайн-заглушки). Текст 18 разделов правил в архив не входил: сопоставление сделано по их краткому изложению в ТЗ и в `ANALYSIS_SYSTEM`.

## 1. Что собой представляет проект

- ~27 тыс. строк Python; `bot.py` — 10 тыс. строк (монолит, см. `CODE_REVIEW.md`). Модули `jf_*` подключаются к одному `dp`.
- Единый реестр команд `cmdcfg` (287 записей по `CHANGELOG 0.11.2`) с иерархией переключателей **global → category → command** и единым хранилищем `cmd_feature_switches` / `cmd_settings`. Это и есть «единый источник состояния»: параллельных источников не найдено; `command_state()` показывает каждый уровень отдельно.
- Единственный архив сообщений — `jf_chat_message_log` (`jf_console.Store`); Justice AI, Watch и Advisor читают его, второй сборщик не создаётся.
- БД на снимке: целостность `ok`; 3 406 записей архива (07.11 19:47 → 08.11 15:40 UTC), 0 сигналов Watch, 0 отчётов, 5 142 записи runtime-лога.

## 3. Найденные проблемы

| № | Серьёзность | Проблема | Статус |
|---|---|---|---|
| F-1 | Высокая | **Редактирование затирало исходный текст** (`ON CONFLICT DO UPDATE SET body=…`) — доказательная база теряла оригинал | Исправлено: `jf_chat_message_revisions` |
| F-2 | Средняя | 7 тестов (`test_ai_analytics` ×3, `test_settings_panel` ×4) никогда не запускались: блок запуска стоял посреди файла (то же, что описано в 0.11.1 для другого файла) | Исправлено |
| F-3 | Средняя | Тест, ранее не исполнявшийся, выявил: 4 фото подряд, где 4-й автор уже был в цепочке, попадали в 4.3 | Исправлено: для медиа 4.3 требует одного автора |
| F-4 | Средняя | При включённом AI цикл Watch спал фиксированные 60 с, `JF_AI_WATCH_POLL_SECONDS` не работал | Исправлено |
| F-5 | Средняя | Фоновые задачи `jf-ai-analytics`, `jf-timers`, `jf-role-sync`, `spy-recovery` без ссылок и без отмены при остановке | Исправлено |
| F-6 | Низкая | `CHANGELOG.md` заканчивался на 0.11.4 при версии 0.13.0 | Исправлено |
| F-7 | Низкая | Тестовая заглушка `aiohttp` без `ClientSession`; `run_all.py` не находил заглушки | Исправлено |
| F-8 | Средняя | Owner-команды `/jf_ai_report|reports|watch|audit|owner` не входят в реестр `/settings` (защищены фильтром ID, но не видны в инвентаризации) | Диагностика сообщает об этом; включение в реестр — этап 4 |
| F-9 | Средняя | В снимке БД **9 из 12 переключателей категорий выключены** (`chat, automation, statistics, moderation, community, profiles, awards, network, events`), `global` включён. Намеренно ли — по данным определить нельзя | Нужна проверка владельцем: `/settings` или `/jf_ai_cmd КЛЮЧ` покажет причину по каждой команде |
| F-10 | Средняя | Сигналы Watch (`jf_ai_watch_alerts`, с Telegram ID и текстом) **не имеют срока хранения** и переживают архив | Требует решения владельца (схема/политика), этап 3 |
| F-11 | Средняя | Семантические сигналы строятся по пакету: псевдонимы участников сбрасываются между пакетами, поэтому **повторяющиеся провокации и травля, растянутые на несколько пакетов, не накапливаются** («история взаимодействия» не реализована полностью) | Этап 3 |
| F-12 | Низкая | Каждый сигнал — отдельное сообщение владельцу; нет разделения «срочно / в сводку» и антишторма | Этап 3 |
| F-13 | Низкая | `jf_ai_watch_alerts` и повторная попытка доставки: при постоянной ошибке отправки попытки идут каждую минуту бесконечно (счётчика попыток нет) | Требует новой колонки → подтверждение |
| F-14 | Инфраструктура | `render.yaml`: план `free`, `JF_STORAGE_DURABLE=false`. SQLite на Render Free не переживает перезапуск; спасает только закреплённый бэкап `JF_DB_BACKUP_V1`. Архив, сигналы и журнал правок теряются при потере диска | Решение владельца (диск или внешняя БД) |
| F-15 | Архитектура | Синхронный `sqlite3` в async-обработчиках (`CODE_REVIEW` п.4); FSM в памяти | Не менялось |

## 4. Вопросы владельцу (R-1, R-2, R-3 решены в 0.13.2: 4.3 — да, 4.5 — любое четвёртое медиа, текст правил получен; R-4 остаётся открытым)

- **R-1.** Правило 4.3: считаются ли четыре одинаковых *текстовых* сообщения от **разных** участников («+», «+», «+», «+»)? Сейчас — да (так закреплено существующим тестом). Если правило про действия одного участника, условие нужно ужесточить.
- **R-2.** Правило 4.5: «четвёртый» — только новый четвёртый участник (как сейчас) или любое четвёртое медиа?
- **R-3.** Прислать текст 18 разделов правил — нужен для точного соблюдения исключений и для разделов 11, 12, 14, которые можно проверять по данным БД (жалобы, `role_history`, игры), а не по переписке.
- **R-4.** Категории «выключены» в снимке — намеренно (F-9)?

## 5. Что требует подтверждения владельца (ТЗ п.13)

- Новая таблица `jf_chat_message_revisions` — **аддитивная** миграция, выполняется автоматически при старте (`CREATE TABLE IF NOT EXISTS`). Включена в пакет, но в production не применялась; для деплоя нужно ваше отдельное разрешение.
- Любые будущие: срок хранения сигналов, счётчик попыток доставки, таблица настроек отчётов/панели, переход на постоянное хранилище.

## 6. План по этапам

1. **0.13.1 (готово, в архиве):** F-1…F-7, диагностика, расширенная самопроверка.
2. **Advisor:** добавить в отчёты локальную статистику без токенов (`jf_stats_hourly/daily`: динамика, часы пик, затишья, участие в играх/мероприятиях, обращения в администрацию); расписание отчётов из панели владельца.
3. **Watch:** история взаимодействий между пакетами (локальные счётчики пар «кто — кому» без Groq), локальные детекторы формальных признаков (рекламные ссылки/приглашения, личные данные), срок хранения сигналов, разделение «срочно / сводка», антишторм, счётчик попыток доставки.
4. **Core:** занести owner-команды в реестр, проверка регистрации обработчиков и пересечений триггеров/callback, плановая самопроверка с срочным уведомлением владельца при fail.
5. **Панель владельца:** разделы Justice AI/Watch/Advisor/Core/Self-Audit/Отчёты/Архив/Ошибки, только рабочие кнопки.
6. **Цикл исправлений (п.13):** только формирование отчёта и предложения патча; применение и деплой — по отдельному подтверждению.

Каждый этап — отдельный пакет с тестами; изменения схемы согласуются заранее.
