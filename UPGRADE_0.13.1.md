# Justice Faite Manager 0.13.2 (включает 0.13.1) — инструкция обновления

Пакет **не загружался на GitHub и не развёртывался на Render.** Деплой — только по вашему отдельному разрешению.

## Что изменилось
См. `CHANGELOG.md` (0.13.1) и `AUDIT_0.13.1.md`.

## Миграция БД (требует вашего подтверждения перед деплоем)
Автоматически при старте создаётся одна новая таблица `jf_chat_message_revisions` и индекс. Существующие таблицы и данные не изменяются и не удаляются. Откат: новая таблица не используется старой версией и безопасно игнорируется.

## Порядок обновления
1. Сделайте резервную копию БД (закреплённый бэкап `JF_DB_BACKUP_V1` или файл `DB_PATH`).
2. Проверьте переменные Render (ниже).
3. Загрузите содержимое архива в репозиторий (вручную, после вашего решения) и дождитесь деплоя.
4. В личном чате с ботом: `/jf_ai_audit` — все строки должны быть 🟢 (🟡 допустимы, если Groq не настроен намеренно), затем `/jf_ai_cmd ai_ask`.
5. Отредактируйте тестовое сообщение в основном чате и выполните `/jf_ai_evidence ID` — должны отображаться обе версии.

## Новые настройки
Новых переменных окружения нет. Добавлены owner-команды `/jf_ai_evidence` и `/jf_ai_cmd` (только личный чат, только `ADMIN_ID`).

## Переменные Render
| Переменная | Значение / назначение |
|---|---|
| `BOT_TOKEN` | токен бота (секрет) |
| `ADMIN_ID` | `1682289834` (в `render.yaml` задан) |
| `PRIMARY_CHAT_ID` | ID основного супергруппового чата |
| `JF_AI_ENABLED` | `true` для живого AI, Watch-семантики и отчётов |
| `JF_AI_API_KEY` | ключ Groq (секрет) |
| `JF_AI_MODEL` / `JF_AI_BASE_URL` | по умолчанию `openai/gpt-oss-20b` / Groq endpoint |
| `JF_AI_ANALYTICS_*` | интервал (3 ч), час ежедневного отчёта (21), смещение (3) |
| `JF_AI_WATCH_*` | вкл., опрос (30 с), семантика (интервал 600 с, минимум 12, пакет 80) |
| `JF_CHAT_ARCHIVE_ENABLED`, `JF_CHAT_LOG_RETENTION_DAYS` (30), `JF_CHAT_LOG_MAX_ROWS` (25000) | архив; журнал правок живёт не дольше самого сообщения |
| `JF_STORAGE_DURABLE`, `DB_PATH` | `true` только при реальном постоянном диске |
