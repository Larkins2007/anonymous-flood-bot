# Render: долговременное хранилище для Justice Faite 0.15.0

Текущий `render.yaml` оставлен на `plan: free`, `JF_STORAGE_DURABLE=false`. Это сделано намеренно: автоматическая смена тарифа могла бы создать расходы.

## Почему это важно

У бесплатных Render web services файловая система эфемерная: локальный SQLite `users.db` может быть потерян при restart, redeploy или spin-down. Free web services не поддерживают persistent disks. У платного сервиса можно подключить persistent disk; данные внутри mount path переживают redeploy/restart. Диск доступен одному экземпляру и ограничивает zero-downtime deploy.

## Вариант для постоянной SQLite-БД

1. Сначала сделайте и скачайте проверенную резервную копию актуальной БД и отдельно проверьте возможность её восстановления.
2. В Render Dashboard измените compute service на совместимый платный план и подключите persistent disk с mount path `/var/data`.
3. В Environment добавьте `DB_PATH=/var/data/users.db` и `JF_STORAGE_DURABLE=true`.
4. Убедитесь, что `JF_ALLOW_EMPTY_DB_BOOTSTRAP=false`, и что архив/резервная копия восстановлены до запуска новой версии.
5. После redeploy проверьте startup logs, `/jf_ai_audit`, количество основных таблиц/записей и владельческий backup. Не удаляйте прежнюю резервную копию, пока не подтверждён запуск.

Persistent disk оплачивается отдельно от compute; актуальную ставку и цену подходящего compute плана нужно проверить в аккаунте Render перед включением. По опубликованной таблице Render цена persistent disk составляет $0.25 за GB в месяц. Бесплатный сервис не может использовать такой диск.

## Без изменения тарифа

Можно оставить текущий Free blueprint, но тогда `JF_STORAGE_DURABLE` должен оставаться `false`; SQLite на локальном диске нельзя считать постоянным хранилищем. Существующее восстановление из резервной копии в личном чате владельца — дополнительная страховка, но не замена persistent disk/managed DB.

## Границы текущей версии

В 0.15.0 нет автоматического создания платного диска, переключения тарифа или production-миграции. Полная замена синхронного SQLite доступа на async/thread storage layer также не выполнена. Не включайте `JF_STORAGE_DURABLE=true`, пока диск действительно не подключён и путь `DB_PATH` не расположен внутри его mount path.
