# Source layout and GitHub policy — 0.24.0

## What belongs in GitHub

Commit application source, `tests/`, `tools/`, `requirements.txt`, `render.yaml`, `.gitignore`, README and maintained documentation. Tests and tools are developer-side assets: they are not automatically launched by the Telegram bot. The release gate invokes them only when an operator runs it.

Do not commit `.env`, API keys, bot tokens, real user databases, SQLite WAL/SHM files, logs, local archives, virtual environments, build output or generated bytecode. `.gitignore` excludes the common local/runtime artifacts.

## Why feature modules remain separate

The small files are not arbitrary fragments: each owns a distinct feature and often has its own registration, persistence or safety boundary. Merging unrelated features would reduce filenames but increase coupling and make testing/deployment riskier. The 0.24.0 change keeps `jf_role_registry.py` separate because it owns a new persistent one-to-one mapping between a character and a Telegram ID.

The next safe step for reducing source clutter is a dependency audit, followed by consolidating only modules that share a domain and lifecycle. `tests/` and `tools/` remain separate and are intended to be version-controlled.
